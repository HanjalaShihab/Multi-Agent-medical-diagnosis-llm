# Multi-agent medical diagnosis: a BTS audit

**Truth Serum or Popularity Contest? Peer-Prediction Mechanisms in Clinical
Multi-Agent Diagnosis.**

This repository contains the literature review, the theory, and a runnable
local-first pilot that audits Bayesian Truth Serum (BTS) as a consensus rule for
multi-agent LLM diagnosis. No API key and no paid service are required.

The pilot tests one claim:

> Under shared evidence, BTS is an **answer-rarity statistic**, not a truth
> statistic. It becomes a truth signal only when the correct answer is a
> minority, i.e. when the team has genuinely private evidence.

The design is built so the claim can fail. It varies one source of
heterogeneity at a time, then evaluates nine pre-registered checks (P1–P8, with
P6 split into P6a/P6b), including an oracle-forecast ablation that separates real
private information from forecast miscalibration.

## Data: five human-written public benchmarks

The pilot uses **only human-written public benchmarks**. It does not use
synthetic or constructed data. Every row below is downloaded from a public
Hugging Face dataset and converted to a local case file; no benchmark item is
generated by an LLM.

| Benchmark | Public source | License | Rows available | Role in the pilot |
|---|---|---|---|---|
| **MedQA-USMLE** | [`GBaker/MedQA-USMLE-4-options`](https://huggingface.co/datasets/GBaker/MedQA-USMLE-4-options), test split | CC-BY-4.0 | 1,273 | 4-option USMLE-style questions; general QA baseline. |
| **PubMedQA** | [`qiaojin/PubMedQA`](https://huggingface.co/datasets/qiaojin/PubMedQA), `pqa_labeled` | MIT | 1,000 | 3-way yes/no/maybe judgement over real abstract sections. **The only benchmark with a genuine H4 evidence partition.** |
| **MMLU-Med** | [`cais/mmlu`](https://huggingface.co/datasets/cais/mmlu), six medical subjects | MIT | 1,111 | Anatomy, clinical knowledge, college medicine, medical genetics, professional medicine, virology. |
| **MedMCQA** | [`openlifescienceai/medmcqa`](https://huggingface.co/datasets/openlifescienceai/medmcqa), validation split | Apache-2.0 | 4,183 | Broad medical entrance-exam QA. The official test split withholds labels (`cop == -1`). |
| **MedXpertQA** | [`TsinghuaC3I/MedXpertQA`](https://huggingface.co/datasets/TsinghuaC3I/MedXpertQA), text test split | MIT | 2,450 | Expert-level questions with up to 10 options. |

**Deliberately excluded.** DDXPlus is a synthetic patient simulator; MedLA /
MedDDx is constructed from a biomedical knowledge base; geteff1 is an
LLM-restructured derivative of case reports. None of them is human-written
benchmark data, so none is part of this pilot. BioASQ is gated and has no easily
downloadable public mirror; treat it as optional and manual.

### Two limitations to state in any write-up

1. **No disease prevalence.** Real QA benchmarks do not carry a patient-population
   prevalence prior. `rarity_stratum` and `prevalence` are therefore `None`; they
   are never inferred from answer-option frequency. P6a is the within-case
   rarity slope of the BTS information score and P6b is the fixed-frequency
   oracle gap. Both are **mechanical properties of the score**. Claims about
   disease rarity or prevalence are **not testable on this suite**.
2. **Only PubMedQA has real evidence sections.** Its slices are the abstract's
   `background`, `case`, `methods`, `results`, `conclusions`, and `other`
   sections, so H4/H5 are a genuine evidence partition. The other four benchmarks
   are text-only; their five slices are contiguous chunks of the question stem.
   H4/H5 there are a **text-chunk ablation**, not evidence partitioning.

## Quick start: real-data smoke test (CPU, about 2 minutes)

This runs the unit tests, prepares a real MedQA subset, executes all cells with
the deterministic mock backend, and writes a report. The numbers are **SMOKE
ONLY**; the point is to verify the pipeline before spending GPU time.

```bash
cd pilot
pip install -r requirements.txt
pip install -e . --no-deps
bash scripts/smoke_test.sh
```

Open `pilot/results/mock_medqa/report.md`. The verdict will say **SMOKE ONLY**.
That is intentional: the mock backend simulates agents.

## Download and prepare the real data

```bash
cd pilot
python scripts/download_data.py all --out data/raw

python -m bts_audit.cli prepare --dataset medqa \
  --raw data/raw/medqa --out data/cases/medqa_300.jsonl --n 300
python -m bts_audit.cli prepare --dataset pubmedqa \
  --raw data/raw/pubmedqa --out data/cases/pubmedqa_300.jsonl --n 300
python -m bts_audit.cli prepare --dataset mmlu_med \
  --raw data/raw/mmlu --out data/cases/mmlu_med_300.jsonl --n 300
python -m bts_audit.cli prepare --dataset medmcqa \
  --raw data/raw/medmcqa --out data/cases/medmcqa_300.jsonl --n 300
python -m bts_audit.cli prepare --dataset medxpertqa \
  --raw data/raw/medxpertqa --out data/cases/medxpertqa_300.jsonl --n 300
```

The downloader uses public `resolve` URLs and the Python standard library, so
`huggingface_hub` is not needed. Review each dataset's license before
redistributing derived case files.

## Full GPU run

On the GPU PC:

```bash
cd pilot
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements-gpu.txt -r requirements.txt
pip install -e . --no-deps
```

Then pick a benchmark. Each config runs H0–H5 plus SYC:

```bash
# MedQA
python -m bts_audit.cli doctor --config configs/pilot_medqa.yaml
python -m bts_audit.cli run --config configs/pilot_medqa.yaml --resume

# PubMedQA (genuine evidence sections)
python -m bts_audit.cli doctor --config configs/pilot_pubmedqa.yaml
python -m bts_audit.cli run --config configs/pilot_pubmedqa.yaml --resume

# MMLU-Med, MedMCQA, MedXpertQA
python -m bts_audit.cli run --config configs/pilot_mmlu_med.yaml --resume
python -m bts_audit.cli run --config configs/pilot_medmcqa.yaml --resume
python -m bts_audit.cli run --config configs/pilot_medxpertqa.yaml --resume
```

Or use the wrapper:

```bash
DATASET=medqa bash scripts/run_pilot.sh
DATASET=pubmedqa LIMIT=60 CELLS=H1,H4,H5,SYC bash scripts/run_pilot.sh
```

The report is written under each config's `output_dir`, for example
`pilot/results/medqa_300/report.md`. A cheaper first pass uses `--limit 60
--cells H1,H4,H5,SYC`; `--resume` continues an interrupted run.

## Experimental design in one paragraph

The pilot varies one source of heterogeneity at a time: H0 consensus (T=0, one
model, one prompt), H1 sampling noise (T=0.7), H2 role prompts, H3 model
families, H4 disjoint evidence slices, H5 evidence plus citations and one
deliberation round, and SYC wrong-answer user pressure. The primary endpoint is
ΔAUC = AUC(BTS) − AUC(confidence). The theory predicts ΔAUC ≈ 0 or negative when
evidence is shared, and recovery only in H4/H5 when evidence is partitioned. An
oracle-forecast ablation (P8) separates real private information from forecast
miscalibration. ΔAUC is one-sided: a large negative value is evidence for the
theory, not a failed run.

## Tests

```bash
cd pilot
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

The suite covers the BTS formulas, parsing, selection rules, AUC/DeLong, the
bootstrap, calibration, the within-case rarity slope, the same-frequency gap,
all five dataset loaders, and an end-to-end mock run.
